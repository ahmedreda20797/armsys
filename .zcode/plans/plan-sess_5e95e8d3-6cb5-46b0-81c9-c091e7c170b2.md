# ARM ERP — Enterprise Quality KPI & Monthly Performance Engine (Phase 1)

Locked design + 8 architectural improvements + milestone order unchanged. Below is the **final consolidated plan** incorporating every rule received. No further rounds needed — proceeding on approval.

## Cross-cutting constraints (enforced in every milestone)

**Backward Compatibility:** Additive only. No existing API response shape changes; existing pages unmodified; no existing module depends on the new engine.

**Database Evolution:** Every new document carries `schemaVersion` (start `1`). Forward-compatible, additive-only future migrations.

**Observability:** `src/lib/api-error.ts` — single `apiError(code, message, {validation?:true})` returning a consistent `{ error:{ code, message, details? } }` JSON shape. Validation failures (4xx, `validation:true`) are distinguishable from runtime failures (5xx). All `catch` blocks emit structured `console.error({ module, op, error })` server logs. No swallowed errors in new code.

**Performance Budget:** Linear-time engines (single-pass `for…of`, `Map`-keyed aggregation). Snapshot generation scales O(employees × observations-per-employee) with no nested loops. Dashboard reads **precomputed snapshots**; only the current month is live-computed. Reuse TTL cache + `getAllBatch` to avoid duplicate reads.

**Security:** Server **always** recomputes scores, totals, ranks, employee names, departments — client-submitted names/departments/scores/calculated values are **never trusted or persisted** (resolved from DB on write/read). All permission checks server-side via existing `verifyPermission`. Mutating routes require `verifyPermission(..., 'approve'|'create'|...)`.

**Maintainability:** One responsibility per module; stable public interfaces; helpers private unless intentionally reusable; business logic only in `lib/` — React components presentation-only; APIs thin.

**Architecture First:** Generic reusable code in shared locations (`lib/approvals`, `lib/audit`, `lib/db-validation`, `lib/idempotency`, `lib/kpi-scoring`, `lib/notifications/quality-events`, `components/shared/{approval,audit,kpi}`); quality-domain code consumes them. Quality is the first consumer of generic primitives, not the only one.

**Code Quality:** No `any` (unless unavoidable + justified), no disabled TS checks, no unjustified ESLint ignores, no hardcoded strings→enums/constants, no duplicated calculations, no hidden side effects, follow existing conventions. No fake/demo/random values anywhere.

**Data Integrity:** Multi-collection writes batched + best-effort rollback + cache invalidation; Close Month idempotent; Reopen reversible (never deletes frozen snapshot); dup-observation guard via `clientRequestId`; FK validation before every write; referential integrity preserved; closed snapshots immutable.

**Production Readiness (per milestone):** no leaks / needless re-renders (memoized selectors + React Query `staleTime`) / dup reads / dup notifications (dedup window) / races (idempotent endpoints) / stale cache (targeted invalidation) / optimistic inconsistencies / orphan records / circular imports / hardcoded IDs or KPI values (config-driven). Mobile layout + dark theme + AOCC + all current functionality unaffected.

**Milestone gate (blocking):** `npx tsc --noEmit` ✓ · `npm run lint` ✓ · `npm test` ✓ · runtime verified ✓ · no regressions ✓. Blocked → finish current only if stable, deliver technical report (root cause / impact / solution / trade-offs), await review.

## Data model (new collections, all with `schemaVersion: 1`)
`qualityObservations`, `observationCategories` (points **and** weight), `observationTemplates`, `kpiSettings` (singleton), `monthSnapshots` (id=monthKey; per-employee frozen `employeeSnapshot` + `settingsSnapshot`; immutable when closed), `qualityAuditLog`. Approval as append-only `approvalHistory[]` (latest projected to `approvalStatus` for fast queries). `clientRequestId` field on observation POSTs for idempotency.

## Generic libs (Milestone 2)
`lib/approvals` (appendApprovalEvent, projectLatestStatus), `lib/audit` (buildTimeline, server logger), `lib/db-validation` (FK + active-employee), `lib/idempotency` (dedupByClientRequest), `lib/kpi-scoring` (computeScoreFromAdjustments, clampScore, PerformanceFactor interface), `lib/kpi-settings`, `lib/observation-categories`, `lib/notifications/quality-events` (reuses Notification Center — no new engine), `lib/api-error`.

## KPI engine + tests (Milestone 3)
`lib/metrics/kpiMetrics.ts` (config-driven; frozen snapshots; trend by `trendCalculation`; timeline derived from audit/approval history; Performance-Engine adapter) → exported from `lib/metrics/index.ts`. `kpiMetrics.test.ts`: floor at `minimumScore`, bonus cap `maximumBonus`, `allowBonus:false`, approved-only, settings-driven behavior, snapshot freezes `employeeSnapshot`, rank, trend, timeline ordering.

## APIs (Milestones 4–6) — thin, delegate to libs
Observations (GET filtered / POST idempotent / PUT-DELETE guarded-if-approved-or-month-closed / approve / reject), categories, templates, settings, audit-log, month-snapshots (list / detail-live-or-frozen / **close idempotent** / **reopen reversible+audited**), kpi-dashboard (`?range=`), migration (admin, idempotent). Each mutating op: FK-validate → dedup-check → write → append approval/audit history → fire notification.

## Permissions + router (Milestone 7)
`permissions.ts`: `observations`, `observationCategories`, `observationTemplates`, `kpiDashboard`, `monthClose`, `kpiSettings`, `qualityAuditLog` with `approve` action; Quality = create/update (no approve), Manager/Admin = approve/override/close/reopen/edit-settings, HR = read. `page.tsx` lazy imports + switch.

## Frontend (Milestone 8)
ObservationsPage (filters, create/edit, Quick-Add templates w/ Favorites+Recently-Used, Apply-Point-Deduction switch, status badges, approve/reject+override, timeline dialog), KpiDashboardPage (range default Current Month; avg score, dept ranking, top/bottom-10 leaderboard w/ trend arrows+medals, pending approvals, category distribution, approval stats), MonthClosePage (grid, Close confirm+snapshot preview incl. frozen employeeSnapshot, Reopen reason), ObservationCategoriesPage (points+weight+color+priority+bonus), KpiSettingsPage.
