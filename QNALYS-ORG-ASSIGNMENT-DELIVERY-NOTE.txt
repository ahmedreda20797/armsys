SCOPE
-----
Employee create/edit is now organization-aware: department/team are
selected from the canonical Organization Tree (no free text), the
selection becomes the employee's canonical orgNodeId, and workforce
strength derives deterministically from active employee records.
Also fixes the two reported layout defects (long node names on tree
cards; overlapping member-management modal).

The existing organization model, scope engine, permission
architecture, membership ledger, audit trails and Firebase Rules are
REUSED unchanged — no parallel org structure was introduced.

EMPLOYEE FLOW — BEFORE / AFTER
------------------------------
Before: free-text القسم input; POST /api/employees accepted no
orgNodeId; assignment possible only from the admin Organization page.

After (create):
  picker → orgNodeId = teamNodeId ?? departmentId
  → server validates node (exists, active) against the live tree
  → display department string DERIVED from the node (nearest
    department ancestor) — never from a client label
  → membershipEvents appends 'joined'
  → tree immediately reflects the employee (counts are derived).

After (edit): a department/team change is an ORGANIZATION TRANSFER.
The generic PUT /api/employees/[id] still REFUSES orgNodeId changes
(M0.4 separation — verified by test). The edit dialog instead shows
an explicit ConfirmDialog naming both nodes, then applies profile
fields via PUT + the pointer via the EXISTING privileged route
POST /api/organization/employees/move (ledger + audit + manager
notifications unchanged). The picker is read-only for users without
'organization' update action (HR preset unchanged).

Legacy contract preserved: POST without orgNodeId keeps the free-text
department path (Excel upload / API consumers byte-identical).

WORKFORCE STRENGTH
------------------
employeeCount / subtreeEmployeeCount / unassignedEmployeeCount are
computed in GET /api/organization from ACTIVE employees' canonical
orgNodeId (filterCurrentEmployees → groupEmployeesByNode →
buildOrgTree). No stored counters exist or were added. Archived and
inactive employees never inflate current strength; restore returns
them to the roster automatically (orgNodeId untouched by lifecycle).
Each employee is counted exactly once — the single-pointer model
makes double counting structurally impossible (test-pinned).

ADD-EMPLOYEE-TO-NODE (member modal)
-----------------------------------
Default filter "بدون إسناد (N)" lists unassigned employees first;
"الكل" shows all eligible. Rows show code, position and the current
node ("ينتمي حالياً إلى: …"); already-assigned employees get a نقل
button gated by an explicit transfer confirmation — never a silent
move. Current rosters exclude non-active employees.

LAYOUT FIXES
------------
Tree cards + list rows + details dialog: every truncatable text sits
in a min-w-0 flex context, so long names truncate at the inline end
(correct ellipsis side for Arabic RTL and English LTR — no direction
hacks) and can never push out badges/buttons; full names remain on
title tooltips + the details interaction.
Member modal: rebuilt on fixed-height rows (h-10/min-h-10), divide-y
separators, non-overlapping flex regions, contained plain scroll
areas (arm-scroll) inside the viewport-bounded dialog.
