## Implementation Plan

### Phase A — Harden the drop pipeline (defensive)

**File: `src/components/pages/workflow-designer/WorkflowDesignerPage.tsx`**

1. **Replace manual transform math with `rf.screenToFlowPosition()`** in the page's drop handler. The canvas currently computes `(e.clientX - x) / zoom` manually from the store transform. The page already has `const rf = useReactFlow()` — wire `onDrop` to use `rf.screenToFlowPosition({ x: event.clientX, y: event.clientY })` directly, ReactFlow's official conversion. Eliminates coordinate drift as a failure cause.

2. **Add `onDrop` try/catch logging** so any silent rejection (defJson missing, parse failure, singleton conflict) becomes visible in dev console and the deliverable report can cite the actual root cause.

3. **Defensive: verify `effectAllowed`/`dropEffect` match** — `onDragStart` sets `effectAllowed='move'`; `onDragOver` sets `dropEffect='move'`. Already correct; will confirm and leave intact.

### Phase B — Enterprise Empty State (Phase 3 of spec)

**File: `src/components/pages/workflow-designer/WorkflowDesignerPage.tsx`** (render inside `<main>`, layered above canvas)

New `CanvasEmptyState` inline component shown when `nodes.length === 0`:
- Large gradient icon (Workflow / Plus)
- Headline: **"ابدأ بسحب أول عقدة من المكتبة"**
- Subtext: **"أو انقر نقرتين لإضافة عقدة بداية"**
- Clickable primary button: **"＋ إضافة عقدة بداية"** → creates a Start node at viewport center via the same creation path as drag
- `pointer-events-none` on decorative wrapper, `pointer-events-auto` only on the button, so it never blocks canvas drag-drop

**Functional double-click:** Add `onDoubleClick` on the `<main>` wrapper that, when target is the pane (not a node) and `nodes.length === 0` (or always, for power-users), creates a Start node at the click's flow position via `rf.screenToFlowPosition`. Satisfies the "double-click to add Start" UX from the approved approach.

### Phase C — Drag Feedback (Phase 4 of spec)

**Files: `WorkflowCanvas.tsx` + `NodeLibraryPanel.tsx`**

1. **Cursor changes** — already present (`cursor-grab active:cursor-grabbing` on NodeCard `:45`). Confirmed, no change.

2. **Drop-zone highlight** — in `WorkflowCanvas`, add `isDragOver` local state toggled by `onDragOver`/`onDragLeave`/`onDrop`. When active, render a translucent violet border overlay + subtle inner glow on the canvas wrapper (`ring-2 ring-violet-500/50`). Gives the "valid drop area highlights" feedback.

3. **Invalid drop cursor** — handled: `onDragOver` sets `dropEffect='move'`; when not over a droppable, browser shows `not-allowed` automatically. Confirmed.

4. **Drop animation** — set `status: 'success'` on the freshly-created node, then revert to `'idle'` after 600ms via `setTimeout` (same pattern already used for edge animation at `:446`). Makes the drop visually "land".

### Phase D — Validation feedback (Phase 5 of spec)

**Already reactive** — `validation = useMemo(() => validateGraphV2(nodes, edges, variables), [nodes, edges, variables])` at `:250`. Any node addition instantly:
- Updates `nodesWithValidation` (`:256`) → node renderer shows error badges
- Updates toolbar badge via `errorCount`/`warningCount` (`:993-994`, rendered `:1033-1037`, `:1169`)
- Updates minimap (canvas reads `nodes` prop which flows through `nodesForCanvas`)
- Updates right panel (inspector consumes `validation` prop `:1197`)

**No code change needed** — will verify wiring intact and add a toast when the new node has validation errors: `toast.info('تمت إضافة العقدة — راجع لوحة الفحص')`.
