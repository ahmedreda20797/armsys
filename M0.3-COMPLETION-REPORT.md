## 1. Executive Summary

M0.3 activated the existing (Milestone 10) data-scope foundation, which was
present but **inert**: no permission entry carried a scope and
`resolvePageScope` defaulted every non-admin to `'all'`.

What changed:

- **Fail-closed default** — a non-admin whose scope cannot be resolved now
  gets `FAIL_CLOSED_SCOPE ('own')` (empty for viewers without the employee
  linkage), never a silent `'all'`.
- **Evidence-based preset scopes on the employees page only** — HR `'all'`
  (workforce administration grants full CRUD), Quality `'all'` (org-wide
  monitoring function), Manager `'subtree'` (managed org nodes ∪ own —
  assignment-driven, never role→data), generic `user` deliberately
  unscoped → fail-closed. No other page was pre-scoped.
- **Scope-tier inheritance inside the single resolver** — an overriding tier
  (position template / stored map) that carries no scope inherits the lower
  tier's scope, so the ~all-stored-overrides-that-predates-scopes cannot
  silently strip a role's configured scope. Chain: `stored.scope →
  position.scope → rolePreset.scope → fail-closed`. Levels/actions/sections
  still replace exactly as before.
- **Employee detail IDOR guard** — `GET /api/employee-360/[id]` (gated on
  the `employees` page permission) now enforces the SAME scope through the
  SAME canonical engine; out-of-scope ids resolve as 404 with a body
  identical to the missing-employee path (anti-enumeration).
- **No second architecture** — `resolveEffectivePermissions`,
  `verifyPermission`, `resolvePageScope`, `resolveEmployeeScope`,
  `filterEmployeesByScope` remain the only permission/scope path; the
  client hook and the Control Panel now delegate to the canonical
  resolver instead of duplicating the rule.

Verification: zero new TypeScript errors, zero new lint problems, 974 tests
(973 pass; the single failure is the documented pre-existing
quality-migration env failure), 37 new M0.3 tests, all M0.1/M0.2/M0.2.1
suites green.

## 2. Existing Organization Model Audit (found, not invented)

- **User** (`arm_erp/users`): role, stored `permissions` JSON (override
  tier), optional `positionId` (position permission template tier),
  optional `linkedEmployeeId` (**the only** user↔employee bridge;
  admin-assigned, 1:1), `isSuspended`. Users are operators, never
  employees.
- **Employee** (`arm_erp/employees`): free-text `department`/`position`
  display strings (never rewritten — historical integrity) + optional
  `orgNodeId` (Milestone 10). Legacy employees have `orgNodeId: null`.
- **OrgNode** (`arm_erp/orgNodes`): generic parent/child tree, depth ≤ 10;
  types `company | department | team | subteam`; `managerUserId` → **User**
  id (the only manager relationship in the model); status/order/manager
  name snapshot.
- **Branch/Organization**: no dedicated entities exist — the tree is
  depth-generic; a "branch" is any intermediate node, the company node is
  the organization level. No duplicates were created.
- **Positions** (`arm_erp/positions`): reusable permission templates,
  middle tier of the single resolver.
- **Employees are not users**: no employee accounts exist or were created;
  the future optional Employee↔User relationship remains exactly the
  existing `linkedEmployeeId` field the scope engine already consumes.

## 3. Existing Scope Architecture Audit

- `DataScope = 'all' | 'department' | 'team' | 'subtree' | 'assigned' | 'own'`
  carried on `PagePermission.scope` (invalid values dropped by
  `migratePermission`).
- `resolvePageScope(permissions, pageKey, role)` — admin → `'all'`;
  otherwise `entry.scope ?? 'all'` (**the inert default M0.3 replaced**).
- `resolveEmployeeScope(viewer, pageKey, permissions, {orgNodes, employees,
  assignments})` — pure resolution against the org graph
  (`src/lib/scope`): team/department = nearest typed-ancestor subtree;
  subtree = managed nodes ∪ own; assigned = assignment pairs ∪ own;
  own = linked employee; non-'all' scopes already failed closed for
  linkage-less viewers.
- `filterEmployeesByScope` — server-side list filter.
- Enforcement existed in exactly one route: `GET /api/employees` (fast path
  when scope === 'all').
- Scope configuration surfaces: Control Panel per-user scope editor
  (existed; stored `'all'` as ABSENT — fixed by M0.3), position templates,
  role presets (previously scope-less).
- `src/lib/reports/scope.ts` contains a **separate, unrelated**
  `resolveEmployeeScope` (report-request employee selection single/
  multiple/all) — untouched, unaffected.

## 4. Final Scope Model

Vocabulary unchanged (`all | department | team | subtree | assigned | own`),
mapping to the M0.3 canonical model:

| M0.3 concept | Existing value |
|---|---|
| ALL | `all` |
| ORGANIZATION | `all` / company-root subtree (no separate value needed) |
| BRANCH | generic intermediate node subtree (department/`subtree` resolve it) |
| DEPARTMENT | `department` |
| TEAM | `team` |
| SELF | `own` (+ fail-closed fallback) |

New exported constants/functions: `FAIL_CLOSED_SCOPE`, `ScopeResolutionSource`,
`ScopeResolution`, `explainScopeResolution()`.

## 5. Scope Resolution Flow

```
authenticated user (JWT → authenticateFromRequest)
    ↓
resolveEffectivePermissions (role ⊕ position ⊕ stored, with scope-tier inheritance)
    ↓
verifyPermission (page/action) — unchanged gate
    ↓
resolvePageScope / explainScopeResolution
    admin                          → 'all'        (source: admin)
    effective entry carries scope  → that scope   (source: configured)
    otherwise (non-admin)          → 'own'        (source: fail-closed)
    ↓
resolveEmployeeScope (org graph → employee-id set)
    ↓
filterEmployeesByScope / ctx.includes() — server-side only
```

Client-supplied role/userId/org/department/team ids never participate.
Query filters intersect the authorized set (`authorizedScope ∩ filters`);
the employees GET reads only the `counts` parameter server-side.

## 6. Organization Assignment Model

Unchanged — by design no new tables or fields were required:
viewer anchor = `users.linkedEmployeeId` → `employees.orgNodeId` (team/
department/own scopes); management reach = `OrgNode.managerUserId ===
viewer.userId` (subtree scope, the manager preset's choice). Multi-team /
multi-department managers already work: `subtree` unions EVERY managed
node's subtree. No many-to-many assignment table was added (the existing
relationship model already expresses it); extending to explicit
multi-assignment tables remains future work if ever needed.

## 7. GET /api/employees Integration

The route already wired `resolvePageScope → resolveEmployeeScope →
filterEmployeesByScope` (Milestone 10). M0.3 changed what feeds it:
admin bypass + HR/quality presets hit the `'all'` fast path (no org-graph
load); the manager preset resolves `subtree`; any unconfigured non-admin
entry fails closed to `own` (empty without linkage). Permission gate
(401 → 403) runs BEFORE scope resolution. Field stripping (M9 mobile) and
`withRelatedCounts` apply to the already-scoped list.

## 8. Query Filters vs Authorization Scope

No server-side department/team/branch filters exist on the employees GET
(only `counts`); client-side filtering happens on the ALREADY-scoped
response, so filters can only narrow — proven by tests (matrix 6, 7, 19).
A scoped viewer requesting out-of-scope ids/teams/departments receives an
empty intersection, never an expansion.

## 9. Unassigned Employee Behavior

Employees with `orgNodeId: null` are excluded from every restricted scope
(team/department/subtree — tested) and remain visible only to `'all'`
viewers (admin/HR/quality). No assignments were fabricated; no default
department was invented.

## 23. Performance Considerations

The `'all'` fast path (admin/HR/quality — the majority of employee-page
viewers) loads no org graph and skips filtering entirely. Scoped viewers
add two list reads (`orgNodes` + `employees` refs) and an in-memory
filter — the engine is pure and the org graph is small (≤ depth 10).
No migration or index changes were introduced (RTDB is schemaless). If
employee-volume ever makes the fetch-then-filter pattern expensive, a
query-pushdown optimization can be a later milestone; documented, not
built.
